SDKs

07 sdks

Three SDKs, and they are not equivalent. The distribution difference decides a language choice before the coverage difference does.

getting them

SDKInstallRegistry
Pythonpip install novai-sdkPyPI, version 0.1.0
Rustgit clone the repository and depend on sdk/novai-sdk by pathnot on crates.io
TypeScriptgit clone the repository and build sdk/novai-sdk-tsnot published to npm

Only the Python SDK can be installed from a package registry. I checked all three registries on 2026-08-29: novai-sdk resolves on PyPI at version 0.1.0, published 2026-05-29, and the SDK source in this repository has not changed since that release. The Rust crate is not on crates.io and the npm package is not published.

The Rust SDK depends on the workspace crates by path (novai-types, novai-crypto, novai-codec, novai-ai-entities), so there is no artifact a registry could carry.

coverage

SurfaceChainRustPythonTypeScript
transaction builders11111110
signal types2323237
memory object types1616165

The Rust SDK re-exports the chain's own type enumerations rather than redeclaring them, so its signal and memory coverage is complete by construction and cannot drift. The TypeScript SDK declares its own copies, which is why it can and does.

The TypeScript SDK is in development and is not a supported signing path. Its coverage gap is stated in numbers below rather than described, because the numbers are the fact.
