 SDKs

 07 sdks

 Three SDKs, and they are not equivalent. The distribution difference decides a language choice before the coverage difference does.

 getting them

 SDK | Install | Registry |

 Python | pip install novai-sdk | PyPI, version 0.1.0 |

 Rust | git clone the repository and depend on sdk/novai-sdk by path | not on crates.io |

 TypeScript | git clone the repository and build sdk/novai-sdk-ts | not published to npm |

 Only the Python SDK can be installed from a package registry. The Rust crate is not on crates.io and the npm package is not published. I checked all three registries on 2026-08-29: novai-sdk resolves on PyPI at version 0.1.0. That is a reading of an external registry taken on that date, not a value this page derives from the repository, so treat it as of then.

 The Rust SDK depends on the workspace crates by path (novai-types, novai-crypto, novai-codec, novai-ai-entities), so there is no artifact a registry could carry.

 coverage

 Surface | Chain | Rust | Python | TypeScript |

 transaction builders | 11 | 11 | 11 | 10 |

 signal types | 23 | 23 | 23 | 7 |

 memory object types | 16 | 16 | 16 | 5 |

 The Rust SDK re-exports the chain's own type enumerations rather than redeclaring them, so its signal and memory coverage is complete by construction and cannot drift. The TypeScript SDK declares its own copies, which is why it can and does.

 The TypeScript SDK is in development and is not a supported signing path. Its coverage gap is stated as numbers in the table above rather than described, because the numbers are the fact.
